# Agent Rules

## Purpose

These rules are mandatory for future branding, design, and UI agents working on the website.

## Non-negotiables

- do not invent a new brand direction
- do not replace the official palette with a new dominant system
- do not introduce generic NGO aesthetics
- do not use pity-based visual or verbal framing
- do not invent unresolved public facts

## Required references

Before doing design work, agents should read:

1. `docs/brand-guidelines.md`
2. `docs/design-system/design-principles.md`
3. `docs/design-system/design-tokens.md`
4. `docs/design-system/page-patterns.md`

## Proposal format for design agents

Any design proposal should state:

- objective
- audience
- pattern used
- key tokens used
- brand rationale
- desktop/mobile behavior
- assumptions or missing information

## Proposal format for frontend agents

Any UI implementation proposal should state:

- pattern being implemented
- tokens mapped to code
- responsive behavior
- accessibility considerations
- any unresolved content dependency

## When agents must escalate

- conflicting public contact details
- exact school addresses not verified
- missing transparency files
- uncertainty around team identities or official roles

## Things agents must not do

- invent new page types without need
- add decorative visuals that weaken clarity
- create many new component variants when an existing pattern fits
- hide institutional trust information behind storytelling
