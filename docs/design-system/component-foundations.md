# Component Foundations

## Purpose

These are the foundational rules for recurring UI elements. They are not a full component library.

## Buttons

### Primary button

Use for:

- donation
- become a member
- key conversion moments

Rules:

- red background
- white text
- strong label
- rounded but not overly soft

### Secondary button

Use for:

- supporting actions
- secondary conversions

Rules:

- outline or warm-accent style
- never compete visually with the primary CTA on the same block

## Links

- links should be clearly identifiable
- text links should not rely only on low-contrast color
- legal and transparency links must prioritize clarity over decoration

## Containers and sections

- use consistent max widths
- generous vertical rhythm
- avoid overcrowding sections with mixed message types

## Cards

### Programme cards

- image-first or image-led
- short summary
- clear action or no action, but not ambiguous

### Support option cards

- title
- clear difference in support path
- amount or contribution type visible where relevant

### Document cards

- sober design
- file title first
- type and year visible
- download/view action obvious

## Team profiles

- dignified portrait
- name and role always visible
- bio optional but compact
- group by governance structure, not by decorative layout logic

## Form foundations

- visually calm
- one clear primary action
- labels always visible
- helper text where needed
- error states accessible and obvious
- payment choices grouped clearly

## Inputs

- consistent height and padding
- clear label + input relationship
- no placeholder-only labeling

## States

Every interactive foundation should support:

- default
- hover
- focus
- disabled
- error
- success where relevant

## Accessibility foundation rules

- focus must remain visible
- color cannot be the only status signal
- buttons and links need clear hit areas
- forms need readable spacing and clear validation
